# 规格条目模板

> 用法：新增或修改规格时复制本模板。每篇编号文档由若干条目组成。
>
> 条目编号规则：`R`=红（安全）、`O`=橙（功能缺陷）、`Y`=黄（清理/文档/小功能）、`G`=绿（质量提升）、`F`=基础设施，后跟序号，如 R1、O3、Y7、G4、F0。
>
> 条目状态机：
> `⬜ 待开发` → `🔴 红（测试未过）` → `🟢 绿（实现通过）` → `✅ 完成（type-check / lint / 全量测试通过并评审）`

---

## [编号] 标题

- **优先级**: 🔴 / 🟠 / 🟡 / 🟢
- **类别**: 安全 / 功能缺陷 / 重构 / 文档 / 基础设施
- **状态**: ⬜ 待开发
- **关联条目**: （如：R3 ↔ Y7 共享模块）

### 问题描述

- 现状：`文件:行` 代码位置与现状说明
- 问题：具体问题描述
- 影响：影响面（用户/成本/维护）

### 目标

一句话描述本条目的完成态。

### 验收标准

- [ ] 标准 1（Given/When/Then 或可断言描述）
- [ ] 标准 2
- [ ] 标准 3

### 技术方案

具体改法：新增/修改/删除的文件、关键实现思路、依赖变更、数据流变化。方案必须足够具体，实施者无需再自行设计。

### TDD 测试计划

> Red 阶段必须完成的测试清单；对应测试未通过（红）之前，不得开始实现（Green）。测试文件与被测文件就近放置（colocated），命名 `*.test.ts(x)`。

| 测试文件 | 测试名 | 断言要点 |
|---|---|---|
| `path/to/x.test.ts` | 名称 | 要点 |
